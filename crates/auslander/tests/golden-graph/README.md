# Golden support tau-tilting graph renderings

Determinism canaries generated by auslander itself. They are not
independent truth. Correctness of the mathematics comes from the derived
pair counts and histograms in `tests/acceptance_tau.rs` and
`src/taugraph.rs`, and from the closure certificate every rendered graph
already passed. Their only job is byte identity:
`tests/determinism_graph.rs` rebuilds each algebra, walks the closed
graph, renders it in the normalized format, and asserts that the bytes
equal the committed file exactly, so any platform, toolchain, or code
change that drifts the walk order, the vertex indices, the slot branches,
the edge order, or any stored witness value fails the suite.

Every value the graph's witnesses store reaches the rendering, either as a
printed field or through a digest. That is what design section 14 asks for,
and a projection of the witnesses is not enough: over F_5 you can scale a
stored forward isomorphism by 2 and its backward partner by 3, and the
witness still verifies with its summand bijection untouched.

Only a `ClosedSupportTauTiltingGraph` is rendered, so every file here
describes a graph that passed `ClosureWitness::verify`. A truncated walk
has no rendering.

The normalized format is documented line by line in the module doc of
`tests/determinism_graph.rs`. In brief: `units=<count>`, then one line per
vertex `v<index> dim=<summands> proj=<support> slots=<records> mod=<digest>
tau=<digest>` in discovery order, then one line per edge `e<index>
<source>:<slot>-><target> shape=<shape> exchanged=<dims> target=<dims>
bij=<map> seq=<digest> iso=<digest> mut=<digest> acp=<digest> add=<digest>
approx=<digest>` in stored order, with LF line endings. A digest is FNV-1a
over a tagged, length-prefixed text payload of the store its field names,
with every matrix and coordinate vector as decimal text. It pins the chosen
matrices, which the indices and dimension vectors do not.
`.gitattributes` marks the files `-text` so git never rewrites their bytes.

| file | algebra | field | pinned content |
| --- | --- | --- | --- |
| `d4-f2.txt` | D_4 with the zero ideal, center at vertex 0 | F_2 | 50 pairs, 100 left-mutation edges |
| `d4-f5.txt` | the same D_4 | F_5 | the same graph, matrices over another field |
| `linear-a3-f5.txt` | linearly oriented A_3, zero ideal | F_5 | 14 pairs, 21 left-mutation edges |
| `radical-square-zero-cycle-3-f2.txt` | the 3-cycle with `rad^2 = 0` | F_2 | 14 pairs, 21 left-mutation edges, on a quiver with a cycle |

A differing byte is a finding. Read the diff before you touch anything:
these files change only when the walk order, a slot branch, an edge, or a
stored witness value changed, and each of those is a determinism defect until
something in the diff explains it. The fresh-process gate in the same file
catches the subset that varies between two runs on one host; a golden
catches the rest, including a change that is stable on this host and
different on another.

Regeneration requires a deliberate rendering or ordering change, recorded
in the CHANGELOG:
`GOLDEN_GRAPH_WRITE=1 cargo test -p auslander --test determinism_graph`.
