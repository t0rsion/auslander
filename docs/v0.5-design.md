# v0.5 design: support tau-tilting, witnessed

This document is the binding specification for v0.5. Implementation follows
it exactly. A deviation needs a documented reason and a design update in the
same commit.

v0.3 moved algebra construction from trusted computation to certified
computation. v0.4 moved the homological layer from dimensions to objects
that carry checkable witnesses. v0.5 moves enumeration from an assertion to
a proof: when the mutation graph closes, the crate holds a certificate that
its list of support tau-tilting pairs is complete.

Consensus basis: Codex thread 019fd9ae (gpt-5.6-sol, xhigh), two rounds,
final consensus on scope, vertex identity, the vanishing-witness tier, the
budget model, closure obligations, the oracle constraints, and the test
tiers. All four spike gates have since reported; section 8 records where the
mathematics changed the agreed design, and section 12 records what the QPA
capability spike allows the oracle to claim.

## 1. Scope

In scope:

- `TauRigidModule` and `TauRigidityOutcome`.
- `BasicDecomposition`, `ProjectiveSupport`, and exact identity for basic
  pairs.
- `SupportTauTiltingPair`: verification of a supplied pair, general, on any
  algebra the crate can build.
- Minimal left add-approximations with factorization data and a
  radical-containment minimality witness.
- Left mutation at a module summand slot, with the Fac branch that proves
  no left mutation exists, and the typed degenerate outputs.
- The budgeted mutation graph, its typed incomplete outcomes, and the
  closure witness.
- QPA oracle schema v7 after a capability spike, Python bindings, a tiered
  acceptance suite, a mutation corpus, and determinism snapshots.

Out of scope, deferred: configurable n-tilting for n greater than one, any
public complex type, the two-term silting bijection (all v0.6 with the
checked complex layer); derived categories, A-infinity structures,
infinite-dimensional quotients, characteristic zero, GPU and parallelism.

The release is NOT additive. `MonomialPresentation` and the monomial
constructors move out of `algebra` into a new `monomial` module that analyzes
and never constructs. `Algebra::from_monomial` and the `Tau` enum go, and so do
three witness types, each for its own reason. `HomVanishingWitness` stored a
whole `HomSpace` to record that its dimension was zero, which is not proof
data; verification recomputed it anyway. `SummandPairVanishing` wrapped the
same non-claim per summand pair. `NonVanishingHomWitness` did store and verify
a real morphism, but it became redundant once the projective part was derived:
a vertex where `M` is nonzero already refutes a proposed `P_v`. In Python,
`Module.tau()` returns the zero module where it returned `None`. The crate is
alpha and breaks between versions by design. Correctness, elegance and
terseness rank above compatibility on this line.

`ClassicalOneTiltingModule` was in scope and was cut before the release was
tagged, and `MinimalRightApproximation` with it. The tilting type verified
one supplied candidate and enumerated nothing, so it carried none of the
release theme; the right approximation had no caller once it went. Section 9
records the first removal and section 7 the second. Mutation and closure were
never weakened to keep either.

## 2. Certification tier

The v0.4 tier carries over: every constructed object is a witness object,
constructible only through a checking constructor, and its `verify()`
recomputes rather than replays. Checks are exact linear algebra over F_p. A
mutation corpus proves each checking constructor rejects tampered data. The
QPA oracle is external differential truth and never carries an internal
cross-check. No serialized certificate format is added; golden normalized
snapshots pin cross-platform determinism.

v0.5 adds one obligation the earlier releases did not have. A completeness
claim is a claim about everything the crate did not enumerate, so it needs
its own witness: `ClosureWitness` (section 8). No function returns a bare
list described as every pair.

## 4. Basic decompositions, projective support, and identity

A pair is `(M, P)` with `P` projective. Both parts are basic: their
indecomposable summands are pairwise non-isomorphic.

```rust
pub struct BasicDecomposition {
    module: Module,
    summands: Vec<IndecomposableModule>,
}

pub struct ProjectiveSupport {
    algebra: Arc<Algebra>,
    vertices: Vec<u32>,   // sorted, deduplicated
}
```

- `BasicDecomposition::new` runs `krull_schmidt`, requires every summand
  certified indecomposable through `IndecomposableModule`, and requires the
  summands pairwise non-isomorphic. A `KrullSchmidtOutcome::Unknown` or an
  `IndecError::Undetermined` is `BasicError::CertificationBlocked`, never a
  silent distinct value and never budget exhaustion.
- A basic projective over a basic quiver algebra is determined by a vertex
  subset, so `ProjectiveSupport` stores sorted vertices and rebuilds the
  canonical sum of `P_i` on demand. Identity of the projective half is
  therefore exact set equality, and cheap.

Pair identity:

```rust
pub enum SupportPairIsoOutcome {
    Isomorphic(SupportPairIsoWitness),
    NotIsomorphic(SupportPairObstruction),
}
```

There is no `Unknown` variant. Both inputs are already certified basic
pairs, and between certified indecomposables the radical criterion used by
`arquiver::category_radical` is total: it either produces an isomorphism or
proves every composite lies in the radical. An undecided comparison between
two existing graph vertices is a crate defect, not an outcome.

`SupportPairIsoWitness` stores the summand bijection and the two-sided
isomorphisms, so `verify()` rechecks by multiplication.

Prefilter, sound and cheap, used before the certified test:

1. Key on the projective support and the sorted multiset of module-summand
   dimension vectors.
2. Refine by Loewy length, top and socle vectors, `dim End`, and residue
   degree.
3. Refine by a Hom-dimension profile against a FIXED anchor family (the
   simples), never against previously found vertices, so the cache never
   becomes state-dependent.

Every fingerprint match stays inconclusive; the exact test is mandatory.
Dimension vectors are isomorphism invariants but not complete identifiers:
the kronecker-2 fixture has three pairwise non-isomorphic indecomposables
with one dimension vector, and the cost spike measured that on the finite
types this prefilter admits only self-matches (50 of 2500 comparisons on
D_4), so identity costs 0.6 microseconds per full scan there.

`AddClosureWitness` proves a module lies in `add(T)`: it stores the basic
decomposition of the module, the basic decomposition of `T`, and for each
summand the index of an isomorphic summand of `T` together with the
certified isomorphism. Mutation approximations use it.

## 5. Tau-rigidity

A VANISHING CLAIM CARRIES NO POSITIVE WITNESS DATA, so no witness type
exists for it. An earlier draft stored a whole `HomSpace` to record that its
dimension was zero, and verification rebuilt that space anyway, so the stored
value proved nothing the recomputation did not.

Private construction of `TauRigidModule` is the proof token instead:
`verify()` recomputes `tau` through the existing double route and checks
`hom_dim == 0`. Construction calls `hom_dim` for accepted pairs and builds a
`HomSpace` only after it sees a nonzero dimension and needs the first
morphism. Verification recomputes at this tier, exactly as
`ProductWitness::verify` recomputes Ext bases and `ArDualityWitness::verify`
recomputes tau. A rank certificate belongs to the serialized untrusted-byte
tier, which v0.5 does not add.

`NonTauRigidWitness` stays, because a nonzero morphism IS positive evidence.

```rust
pub enum TauRigidityOutcome {
    TauRigid(TauRigidModule),
    NotTauRigid(NonTauRigidWitness),
}
```

- `M` is tau-rigid when `Hom(M, tau M) = 0`. `TauRigidModule` stores the
  summands and their certified translates, not an assembled module;
  `verify()` recomputes `tau` through the existing double route and rechecks
  that `hom_dim` is zero. `TauCache` is keyed by nominal module identity, not
  by a caller-supplied index: an index-keyed cache guarded only by dimension
  vectors returned a wrong translate over kronecker(2).
- `NonTauRigidWitness` carries one nonzero morphism `X_i -> tau X_j`, which is
  a nonzero element of `Hom(M, tau M)`, so the negative result is as checkable
  as the positive one.
- The zero module is tau-rigid. The pair `(0, A)` is a legitimate vertex.

PERFORMANCE RULE, binding. Never call `tau` on an assembled module. `tau`
and `Hom` are both additive, so tau-rigidity of `M = X_1 + ... + X_s` is
decided by `hom_dim(X_i, tau X_j) = 0` for all `i, j`, with `tau` computed
once per indecomposable and cached. Working per summand avoids running the
double-route cross-check on a decomposable module, where it decomposes both of
its results. How much of `tau` that accounts for is not claimed: the wall-clock
figures that once stood here predate the identity-keyed cache and were removed
rather than carried forward. The exactness follows from additivity and is not
a heuristic, so it does not weaken the certified route. Every `tau` the crate
uses still runs both routes and cross-checks them, on an indecomposable where
that check is cheap.

`opposite` is cached per `Arc<Algebra>`, worth 25 to 45 percent of a `tau`
on an indecomposable, which is where every `tau` call lands after the rule
above.

## 6. Support tau-tilting pairs

```rust
pub struct SupportTauTiltingPair {
    module: BasicDecomposition,
    rigid: TauRigidModule,
}
```

`SupportTauTiltingPair::new(module, projective)` checks, in this order:

1. Both parts are basic and certified (section 4).
2. `Hom(P_v, M) = M_v`, decided on the dimension vector. For right modules
   `P_v = e_v A`, and evaluation at `e_v` is a bijection
   `Hom(P_v, X) -> X e_v = X_v`, so a basic projective `P` has `Hom(P, M) = 0`
   exactly when its vertex set lies in the support complement. No witness
   object is stored: a vertex with `M_v` nonzero already refutes a proposed
   `P_v`.
3. `M` is tau-rigid, decided summandwise per section 5.
4. `|M| + |P| = n`, where `n` is the number of vertices and `|X|` counts
   indecomposable summands.

THE PROJECTIVE PART IS FORCED, so it is derived and not stored. Write
`r = |M|`, `s = |supp M|`, and `C` for the support complement. Condition 2
gives `S` contained in `C` for the vertex set `S` of `P`, condition 4 gives
`|S| = n - r`, and `r <= s` holds by AIR Lemma 2.1(a) with Proposition 1.3
(pass to `B = A/AeA` for `e` the sum of `e_v` over `C`, where `M` stays
tau-rigid and `B` has `s` simples). Then `|S| = n - r <= n - s = |C|` with `S`
inside `C` forces `S = C` and `r = s`. A pair exists exactly when `r = s`.

`is_tau_tilting()` reports whether the projective part is empty. An
almost-complete pair satisfies the same conditions with `|M| + |P| = n - 1`;
it has its own type `AlmostCompletePair`, since mutation is defined through
it. There the count gives `|C| - |S| = r - s + 1`, which is at most 1 by
`r <= s` and at least 0 by containment, so `s` is `r` or `r + 1` and `P` is
either all of `C` or `C` minus exactly one vertex. `AlmostCompletePair` stores
that as one optional omitted vertex; no third case exists.

Basicness is required, since the indecomposable projectives are exactly the
`n` pairwise non-isomorphic `P_v`, and `Algebra` guarantees it by only
building `kQ/I` with `I` admissible. Connectedness is NOT required.

## 7. Minimal approximations

For `f: X -> B` with `B` in `add(N)`:

- `f` is a left `add(N)`-approximation when every map `X -> N'` with `N'` in
  `add(N)` factors through `f`. The witness stores, for every basis map from
  `X` into every indecomposable summand of `N`, the factorization
  coordinates through `f`.
- `f` is LEFT MINIMAL exactly when
  `K_f = ker(End(B) -> Hom(X, B))`, `h |-> f.then(h)`, is contained in
  `rad End(B)`. The witness stores the RREF basis of `K_f` in `End(B)`
  coordinates and the coordinates placing each basis vector inside
  `rad End(B)`. `EndoAlgebra` supplies both; `category_radical` alone does
  not establish minimality when `B` is decomposable.

The right versions were specified here and cut with section 9: left mutation
is the only production caller of the approximation layer, and it needs the
left side alone.

The spike must exercise a fixture with residue degree greater than one: an
F_p basis of `Hom` is not automatically a minimal generating family over a
larger residue division ring.

## 8. Left mutation and the closed graph

### Field generality, settled

Both results this release depends on hold at the crate's generality, finite
dimensional algebras over an arbitrary field, with no algebraically closed
hypothesis and no restriction on residue division rings.

- T1, an almost complete support tau-tilting pair has exactly two
  completions: Adachi, Iyama, and Reiten, "tau-tilting theory", Compositio
  Math. 150 (2014), Theorem 2.18.
- T2, for `U < V` there is a left mutation `V'` of `V` with `V' >= U`: same
  paper, Theorem 2.35(b). Corollary 2.38 is a pointer to where the descending
  half of the proof lives, not the citation the certificate rests on.

The paper's introduction says "algebraically closed", but section 5 states
"in the rest of this paper we assume that our base field k is algebraically
closed". That sentence is vacuous unless sections 1 through 4, which contain
both results, hold over an arbitrary field; section 2 opens over any finite
dimensional k-algebra. Demonet, Iyama, and Jasso, "tau-tilting finite
algebras, bricks and g-vectors" (arXiv:1503.00285), work over an arbitrary
field with right modules, which is exactly this crate's setting, restate
Theorem 2.18, and state that the underlying graph of the support tau-tilting
quiver is |A|-regular with |A| the number of simple modules. Those citations
carry the two further facts this release uses: a basic support tau-tilting
pair has exactly n indecomposable summands, and the quiver is n-regular.

No proof step needs `End(X)/rad End(X)` to be the base field. The one place
that assumption would enter silently is the multiplicity in a minimal
approximation, which section 7 handles over the residue division ring.

AIR state their results for left modules. That costs nothing here: the
theorems are universally quantified over finite dimensional algebras, so
instantiate them at the opposite algebra. No dualization is needed anywhere
in the construction.

Erratum worth recording, because a reader will hit it: the tau display in
AIR has the arrow direction transposed. The correct sequence is
`0 -> tau X -> nu P_1 -> nu P_0`. This crate's `ar.rs` already implements the
correct form. Do not "fix" it to match the paper.

### The certificate needs left mutation only

AIR reach every vertex of the component of `(A, 0)` by descending, using
Theorem 2.35(b), which only steps down. So the walk starts at `(A, 0)` and
closes under LEFT mutation alone. The citation is 2.35(b) and NOT Corollary
2.38: a direct appeal to 2.38 would additionally have to rule out a mutation
from outside the set landing inside it, which the walk never checks.

Consequences, all of them simplifications:

- No Bongartz completion, no `tau^-1`, no transpose, no right mutation.
- No indecomposable enumeration and no AR quiver.
- Mutation at a projective summand is always a right mutation, so the
  descending walk never performs one. The `MutationSlot` split into module
  and projective kinds is therefore unnecessary: a slot is an index into the
  module summands of the pair.
- n-regularity becomes a cross-check rather than a soundness requirement.

This is a deviation from the earlier consensus, which required signed slots
covering both kinds and all four transitions. The mathematics removes the
need rather than the obligation: the earlier design was correct but bought
machinery the certificate does not use.

### Slots and the two branches

For a vertex `(M, P)` with module summands `X_1, ..., X_m`, slot `j`
addresses `X_j`. Exactly one of two things holds, and the implementation
decides which without guessing:

1. `X_j` is in `Fac(M/X_j)`. Then the mutation at slot `j` is a right
   mutation and the walk records NO outgoing edge. Membership is decided by
   rank: a finite family `f_i: U -> X` proves `X in Fac U` as soon as the sum
   of its images is `X`, equivalently as soon as the induced `U^r -> X` is
   onto. `FacWitness` stores that family and the summands of `U`. Verification
   checks endpoints, reassembles `U` from its stored summands, and compares
   one vertexwise image rank. It does NOT rebuild `Hom(U, X)` and does not
   claim the family spans it: spanning is strictly stronger than the
   definition of `Fac`.
2. Otherwise the left mutation exists. Build the minimal left
   `add(M/X_j)`-approximation of `X_j` (section 7, multiplicities over the
   residue division rings), take its cokernel, and assemble the new pair.
   Degenerate outputs are typed, not silent: a zero cokernel moves the slot
   to the projective part of the new pair.

Adjacency is then proved theorem-level and uniformly: drop `X_j`, verify
both endpoints extend the resulting almost complete pair, verify the signed
complements differ, and verify the target is a support tau-tilting pair. T1
identifies the target as the unique other completion, hence as the mutation.
The exchange sequence is stored as an additional construction witness, never
as the adjacency proof.

### Closure witness

`ClosureWitness::verify()` rechecks all of:

1. Every vertex is a verified basic support tau-tilting pair.
2. Vertices are pairwise non-isomorphic.
3. Vertex zero is certified isomorphic to `(A, 0)`.
4. For every vertex and every slot, either a verified left mutation whose
   target is a vertex of the set, or a certified `Fac` membership proving no
   left mutation exists at that slot.
5. Every edge endpoint carries a stored pair-isomorphism witness to its
   indexed vertex.
6. The set is connected to `(A, 0)` by directed left-mutation edges,
   rechecked independently rather than inferred from the walk that built it.
7. As a cross-check, not a soundness requirement, every vertex has exactly n
   slots and the undirected degree count agrees with n-regularity.

`ClosedSupportTauTiltingGraph` may then expose the complete list. Its
provenance is T2 applied to a finite LEFT-CLOSED set containing `(A, 0)`.
The recheck is a gate, not a courtesy: the type is constructed only after
`ClosureWitness::verify()` passes, and a failure is `GraphError::Defect`.

Completeness rests on obligations 1 to 5. Obligation 6 follows from them, and
obligation 7 is outside the argument; both remain gates. Connectivity and
n-regularity are NOT load-bearing. The argument: `(A, 0)` is the maximum; for
any pair `U`, if `V` is in the set and `V > U` then T2 gives a left mutation
`V' < V` with `V' >= U`; left closure puts `V'` in the set; finiteness forbids
an infinite strict descending chain, so the process stops only at `U`. Hence
no omitted vertex can coexist with finite left closure.

An `IsoOutcome::Unknown` or an `IndecError::Undetermined` anywhere in the
walk poisons the certificate: the outcome becomes
`Incomplete(CertificationBlocked)`. It is never treated as "probably fine"
and never as budget exhaustion.

### Truncation is structurally biased, and must say so

On a tau-tilting infinite algebra the descending walk runs down one ray
forever. On the Kronecker algebra it descends the preprojective ray and
never reaches a single preinjective vertex, so a truncated result is a
biased sample rather than a nearly complete list. The `Incomplete`
documentation says this plainly. The safe direction holds: a truncated set is
never accidentally closed, so no false completeness certificate is possible.

### Vertex identity and g-vectors

Minimal presentation matrices give g-vectors directly, and they are a sound
prefilter. Cite Demonet, Iyama, and Jasso for any g-vector statement, not
AIR Theorem 5.5, which sits inside the algebraically closed section. Note
that the DIJ companion result, that a g-vector inequality forces an
epimorphism, requires an infinite field and is therefore unusable here. The
certified isomorphism test remains mandatory.

### Outcomes and budget

```rust
pub enum SupportTauTiltingGraphOutcome {
    Closed(ClosedSupportTauTiltingGraph),
    Incomplete(IncompleteSupportTauTiltingGraph),
}

pub enum IncompleteReason {
    BudgetExhausted(GraphBudgetDiagnostics),
    CertificationBlocked(CertificationBlocker),
}
```

`Incomplete` retains the partial graph; its vertices and edges stay
individually certified. Accessors are named `vertices_found` and
`verified_mutations`, never `all_pairs`. Neither incomplete reason raises in
Python: both return an `IncompleteSupportTauTiltingGraph` carrying the reason,
which keeps the rule that a mathematical outcome is a value. A defect
contradiction is an error, not an incomplete outcome.

```rust
pub struct MutationGraphLimits {
    max_vertices: usize,          // default 10_000
    max_directed_mutations: usize,// default 100_000
    max_work_units: u64,          // default 50_000_000
    max_matrix_entries: usize,    // default 4_000_000
}
```

Defaults are grounded in the cost spike. D_4 has 50 vertices and E_7 has
4160, so 10_000 admits every finite type through E_7 and stops before E_8's
25_080. The measured worst-case `Fac` system in the fixture set is 2950
entries; E_7's worst case is 2_666_520 entries and fits, while E_8's
38_235_366 entries (306 MB at 8 bytes per `Fp`) truncates with a typed
error instead of allocating. `max_matrix_entries` gates ONE Hom system
per slot, the `Fac` test `Hom(U, X_j)`, and nothing else. Fingerprinting,
decomposition, target classification, and the systems inside `tau` fall
outside it, because none of them can be sized before the call that builds
them. `max_work_units` is what bounds those, by size as well as by call count.
There are no wall-clock limits anywhere. They would break determinism.

`max_vertices` is checked when inserting a further DISTINCT vertex, so a
budget equal to the true count still permits closure. That does NOT carry over
to `max_work_units`: the slot precheck reserves the left-mutation cost before
the branch is known, so a `Fac` slot charges less than its reservation, and a
ceiling set exactly at the charged count can still truncate. D_4 charges
3951020 units and does not close under a ceiling of 3951020.

`max_work_units` is enforced after every slot and again when the frontier
drains, so a `Closed` outcome never reports more units than its budget. The
closure recheck is not charged: it runs over the result, not the search.

Diagnostics carry vertices found, verified directed slots, new vertices
versus repeated endpoints, frontier size, the current vertex and slot, open
slots, work units consumed, and the exact limit hit.

Deterministic work-unit model, charged by call and by module size, never by
time. One unit is one unknown of one Hom system. Every rate names a number of
Hom systems and multiplies it by the size factor

```text
e = max(1, sum_v (dim M_v)^2)
```

the unknown count of `Hom(M, M)` for the module the walk stands on:

```text
hom_dim / HomSpace::new(M, N)         = e units
IndecomposableModule::new             = 8 * e units
krull_schmidt / decompose, s summands = 8 * s^3 * e units
is_isomorphic(M, N), s summands       = (8 * s^3 + 16) * e units
tau(M), s summands                    = (64 * s + 8 * s^3) * e units
```

`e` bounds the unknown count of each system in the modelled sequence, because
every argument is a summand of `M` or a simple module and `sum_v dim U_v dim
W_v` is at most `sum_v (dim M_v)^2` when `U` and `W` are summands of `M`. It
does not bound the systems inside `tau`, whose translate is not known before
the call; that term keeps its unscaled rate, scaled by the standing module.

The size factor is what makes `max_work_units` brake a tau-tilting infinite
walk. Charging by call alone did not: on the Kronecker preprojective ray the
modules grow without bound, so a Hom system far out along the ray cost far
more than one near the start and was charged the same single unit, and no
ceiling fired before the walk became unusable.

Counts are exact and field-independent, so the same assertions hold on the
Windows CI runner that stalled during v0.4. Ceilings asserted in
`taugraph::tests::the_work_unit_counts_stay_under_their_ceilings`: A_2 16_384,
A_3 524_288, A_4 8_388_608, D_4 8_388_608. A finite type larger than the
fixture set can charge past the 50_000_000 default, so raise the budget rather
than read exhaustion as tau-tilting infiniteness.

## 9. Classical one-tilting, cut

`ClassicalOneTiltingModule` was specified here and removed before the tag.
It verified one supplied `T` against `pd T <= 1`, `Ext^1(T, T) = 0`, a
checked `0 -> A -> T^0 -> T^1 -> 0`, and two `AddClosureWitness` values. It
enumerated nothing and contributed nothing to the closure certificate, and
its projective dimension stopped at one only because the checked complex
layer does not exist yet. Tilting comes back with that layer, where the
generation axiom for `n` above one is a checked exact complex rather than a
single sequence.

The number 9 stays with this section so the later section numbers keep the
meaning the tests cite.

## 10. Second verification route

The acceptance suite enumerates support tau-tilting pairs a second way,
from the DEFINITION only, never through mutation:

- Precompute `tau X_i` for every entry of an exhaustive
  `IndecomposableCatalog`, then the tables `hom_dim(X_i, tau X_j)` and
  `hom_dim(P_v, X_i)`.
- Walk subsets by depth-first search, extending only tau-rigid sets, and
  keep those with `|M| + |P| = n`.

This is exact rather than approximate, because `tau` and `Hom` are additive.
The cost spike confirmed the counts against published W-Catalan numbers:
semisimple on n vertices gives 2^n; A_2 5, A_3 14, A_4 42, A_5 132, A_6 429,
A_7 1430; D_4 50, D_5 182, D_6 672; E_6 833; E_7 4160. It also confirmed
truncated_poly(3) 2, linear_nakayama([2,2,1]) 12, and
radical_square_zero_cycle(3) 14. The route runs under 4 ms through E_7.

A literal route that assembles each candidate module and calls `tau` and
`hom_dim` directly is kept as a third check where it is affordable: it is
feasible through D_5 at 13.8 s and stops there.

Exhaustive tier, opt-in through `#[ignore]` or an environment variable and
NOT gated on `--release`: the literal route on D_4 over F_5, A_5, D_5, and
A_6; the full primitive sweep. The cross-check that the summandwise route
agrees with the literal definition is NOT a graph walk: it compares the
assembled and summandwise routes over the 299 subsets of size at most three of
D_4's 12 indecomposables, in
`taurigid::tests::summandwise_agrees_with_the_assembled_route_on_every_small_d4_subset`.

The cost spike measured that release buys only 1.2x to 2.2x over the dev
profile at `opt-level = 2`, because the residual gap is debug assertions rather
than codegen. There is no order-of-magnitude tier to unlock by gating on
release.

Tests assert deterministic work-unit ceilings, never elapsed time. Measured
counts with the ceiling asserted, about twice measured and rounded up to a
power of two: A_2 6668 units, assert 16384; A_3 145712, assert 524288; A_4
2253257, assert 8388608; D_4 3951020, assert 8388608. These counts moved when
the rates gained the size factor `e`, so remeasure rather than copying them
forward.

The Kronecker algebra is tau-tilting infinite and has no exhaustive
catalog. Both catalog constructors reject it with typed errors. A bounded
walk with `max_vertices = 16` must return a typed truncation rather than
hang, which exercises the walk, verification, and identity code against a
tau-tilting-infinite input.

## 12. QPA oracle schema v7

QPA 1.36 has no support tau-tilting predicate, pair type, mutation, or
enumerator, and no silting. The spike established what can still be built
from QPA primitives alone, and schema v7 carries only that.

Binding constraints:

- Oracle fields are basis-independent invariants only.
- Modules are designated by construction, never looked up by dimension
  vector.
- `qpa_expected.json` is regenerated only by a real GAP run per the oracle
  README, never from library output.

The independent enumeration route is an AR-quiver walk: seed with the
indecomposable projectives and injectives, close under
`IrreducibleMorphismsEndingIn` and `IrreducibleMorphismsStartingIn`, and
deduplicate with `IsomorphicModules`. Do NOT close under
`AlmostSplitSequence`: during the spike that operator silently returned one
indecomposable instead of three on `k[x]/(x^3)`, because a
projective-injective module has no almost split sequence in either
direction. `AllIndecModulesOfLengthAtMost` is the cross-check where it is
affordable, and it errors when a length class is empty.

Fields, with their gates:

- Total pair count and the histogram by module-summand count, admissible
  ONLY for fixtures whose walk closed. Each carries a typed closure marker,
  either closed with the indecomposable count or not closed with the cap.
  A truncated walk still yields a plausible number, so an ungated total
  would be a silent undercount: on kronecker-2 the length-3 truncation
  reports 5 pairs.
- Sorted projective-support vertex subsets, 0-based. The spike measured that
  the projective part always equals the zero support of the module part, so
  this is a redundancy check rather than new information.
- Per-pair sorted lists of module-summand dimension vectors, as an
  explicitly WEAK value field. Repetitions are preserved, never merged, and
  never read as multiplicity or identity. The v6 merging helper must not be
  reused here: `cyclic-nakayama-3-3-3` has three pairwise non-isomorphic
  projectives that all have dimension vector `[1, 1, 1]`, so a repeated
  entry there is distinct modules, not multiplicity.
- Tau-rigidity booleans per designated module, as in v6.
- Approximation invariants only: source and target dimension vectors, rank,
  kernel and cokernel dimension vectors. NOT a mutated-pair identity. QPA
  realizes the exchange only when the approximation is injective with
  nonzero cokernel; on D_4 that is 50 of 150 module-summand mutations, and
  the other branch gives the wrong partner half the time.
- Classical one-tilting booleans with the projective dimension and
  coresolution term dimension vectors, restricted to the enumerated pairs
  with n summands. Extract the coresolution with `LowerBound` and
  `UpperBound` guarded by `IsZeroComplex`; `LowestKnownDegree` returns minus
  infinity on a finite complex and then fails. Never call `IsTiltingModule`
  without calling `TiltingModule` first: it is an attribute with no
  computing method, and a false answer never sets it. With section 9 cut,
  the generator still writes this field and the reader accepts it and
  compares nothing. Schema v8 drops it, so that the committed document stays
  the bytes the GAP run produced.
- Exchange graph shape (degree histogram, edge count, connectivity), clearly
  labeled a self-consistency check rather than external truth, since it is
  computed from the crate's own enumerated set.

Harness defect to fix in this pass: `gap -q -T` with closed stdin exits 0
after an uncaught error, so the existing `output.status.success()` assertion
is vacuous and only the output-file check catches a failed run. The oracle
README states the opposite and must be corrected. Keep the generator writing
its output in one final statement.

`NumberOfNonIsoDirSummands` must not be used at all: its second entry is the
dimensions of the simple blocks of `End(M)/rad End(M)`, not multiplicities.
`DecomposeModule` and that function both error on the zero module.

## 13. Python surface

- `Module.tau_rigidity()` returns a `TauRigidity` result exposing
  `is_tau_rigid`, the witness, and `verify()`; the negative case exposes the
  witnessing morphism.
- `SupportTauTiltingPair` construction from a module list and a vertex list,
  with `module_summands`, `projective_support`, `is_tau_tilting`, and
  `verify()`.
- `Algebra.support_tau_tilting_graph(limits=None)` returns either a closed
  graph exposing `pairs()`, `mutations()`, and `verify()`, or an incomplete
  result exposing `vertices_found`, `verified_mutations`, `reason`, and the
  diagnostics. The incomplete value never exposes a `pairs()` accessor.
- Error taxonomy follows v0.4: invalid input raises `ValueError` subclasses
  and a defect raises `DefectError`. Mathematical outcomes never raise, so
  budget exhaustion and blocked certification are VALUES: both return an
  `IncompleteSupportTauTiltingGraph` carrying the reason, rather than the
  exceptions an earlier draft of this section named.

## 14. Determinism

Deterministic across processes and platforms: catalog order, the walk order
(breadth first from `(A, 0)`, module-summand slots in increasing order),
vertex indices in discovery order, the prefilter keys, and every stored
witness. There are no signed slots: v0.5 takes left mutations only.

Gates, in `tests/determinism_graph.rs`: a fresh-process fingerprint over the
graph renderings, and committed golden normalized renderings compared byte for
byte under `tests/golden-graph/`, in the style of `tests/golden-ar/`.
Regenerate a golden only after a deliberate format change, with
`GOLDEN_GRAPH_WRITE=1`.

## 15. Mutation corpus

Every checking constructor and every `verify()` rejects a targeted
mutation: a non-basic decomposition presented as basic; a pair whose summand
count is off by one; a borrowed `TauRigidModule`; an omitted vertex outside
the support complement; a `NonTauRigidWitness` whose morphism is zero; an
approximation witness missing one factorization; a minimality witness whose
`K_f` basis leaves `rad End(B)`; a mutation witness whose target is not a
support tau-tilting pair; a closure witness with a missing slot, a duplicated
vertex, a broken involution, or a graph disconnected from `(A, 0)`.

## 16. Style

`docs/writing-style.md` binds all prose. New code is ASCII in comments and
docstrings, matching the v0.4 witness layer. Names never overclaim:
`vertices_found` is not `all_pairs`, and a graph that hit a budget is never
described as an enumeration.
