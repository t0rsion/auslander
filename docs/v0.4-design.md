# v0.4 design: the Auslander-Reiten layer, witnessed

This document is the binding specification for v0.4. Implementation follows
it exactly. Deviations require a documented reason and a design update in
the same commit.

The theme repeats the v0.3 jump at the next level: v0.3 moved algebra
construction from trusted computation to certified computation. v0.4 moves
the homological layer from computing dimensions to producing objects that
carry checkable witnesses. One pipeline, end to end: Ext classes, actual
extensions, the distinguished AR class, almost-split sequences, irreducible
morphisms, valued AR quivers.

Consensus basis: Codex thread 019fd304 (gpt-5.6-sol, xhigh), three rounds,
final confirmation of scope, certification tiers, witness gating, valued AR
quiver, catalog domains, QPA-spike-before-schema-v6, Python surface, error
taxonomy, and the ten design bullets. All ten bullets appear below as
binding sections.

## 1. Scope

In scope:

- First-class `HomSpace` with subspaces, quotients, deterministic
  complements, and coordinates.
- `IndecomposableModule`, a checked wrapper tied to its End-locality proof.
- `ExtSpace` and `ExtClass`: Ext groups as explicit vector spaces with
  recheckable representative data.
- Yoneda products by stored chain lifts, composed with `then`.
- Checked `ShortExactSequence`, construction from an Ext^1 class, class
  recovery, split witnesses, non-split inconsistency witnesses.
- Maps factoring through projectives, stable Hom, the AR socle criterion,
  and `AlmostSplitSequence` gated behind explicit witnesses.
- Category radical, typed exhaustive indecomposable catalogs, catalog-exact
  rad^2, irreducible morphism spaces, valued AR quivers.
- QPA oracle schema v6 (after a capability spike), Python bindings for the
  full decision surface, acceptance matrix, mutation corpus, determinism
  snapshots.

Out of scope (deferred, in order): witnessed tilting and support tau-tilting
(v0.5); checked chain complexes and Hochschild cohomology (v0.6); derived
categories, A-infinity structures, stable and singularity categories,
infinite-dimensional quotients, characteristic zero, GPU and parallelism.

The release is additive. No public v0.3 API is removed or changed.
`ext_dim`, `ext_table`, `tau`, and every other v0.3 entry point keep their
signatures and behavior.

## 2. Certification tier

v0.3 certified untrusted bytes: a bad completion could create an unsound
`Algebra`, so an independent verifier re-checks everything from serialized
input. v0.4 objects derive from an already verified `Algebra` and from
checked `Module` and `Morphism` values. That is a different trust boundary.
The tier for v0.4 is:

- Every constructed object is a witness object: it carries enough data to
  recheck the claim its type makes, and it is constructible only through a
  checking constructor. No public field permits building an unchecked
  value.
- Checks are linear algebra over F_p: rank equalities, multiplication
  identities, membership of vectors in row spaces. All exact.
- A mutation corpus proves each checking constructor rejects tampered data
  (section 15).
- The QPA oracle is external differential truth. Internal cross-checks are
  never oracle fields.
- No serialized certificate format is added. Golden normalized snapshots
  pin cross-platform determinism (section 14).

New files in `crates/auslander/src/`:

- `homspace.rs`: `HomSpace`, `HomSubspace`, `HomQuotient`.
- `indec.rs`: `IndecomposableModule`, `IndecError`.
- `sequence.rs`: `ShortExactSequence`, `SplitStatus`, `SplitWitness`,
  `NonSplitWitness`, `SequenceError`.
- `almost_split.rs`: projectively trivial maps, stable Hom, the AR socle

- `arquiver.rs`: `IndecomposableCatalog`, `CatalogProvenance`, category

`homspace.rs` builds on them.

## 4. HomSpace (design bullet 3: ownership, transport, equality)

```rust
pub struct HomSpace {
    source: Module,
    target: Module,
    basis: Vec<Morphism>,
    flat: DenseMat,
}
```

- `HomSpace::new(m: &Module, n: &Module) -> Result<HomSpace, HomError>`.
  The basis is exactly `hom(m, n)` in its existing deterministic order
  (kernel of the commuting-square system, variables vertex-major then
  row-major, free columns in increasing index). `flat` stacks each basis
  morphism's per-vertex matrices row-major into one row of length
  `sum_v dim M_v * dim N_v`.
- `dim()`, `source()`, `target()`, `basis()`, `morphism(coords: &[Fp])`,
  `coords(f: &Morphism) -> Result<Vec<Fp>, HomSpaceError>`.
- Compatibility rule: two `HomSpace` values are compatible when their
  sources are `ptr_eq` and their targets are `ptr_eq`. Because the basis
  construction is deterministic, recomputed compatible spaces have
  identical bases, and coordinates transport verbatim. `coords` on a
  morphism whose endpoints are not `ptr_eq` to the space's endpoints is a
  typed error, never a silent reinterpretation.

Subspaces and quotients:

```rust
pub struct HomSubspace { /* parent endpoints + RREF row basis over flat coordinates */ }
pub struct HomQuotient { /* subspace + deterministic complement rows */ }
```

- A `HomSubspace` always stores its basis as the RREF of its spanning set
  in flat coordinates. Two subspaces of compatible spaces are equal exactly
  when their RREF matrices are equal.
- `HomSubspace::contains(f)` is a row-space membership test.
- Deterministic complement rule, fixed crate-wide: to complement subspace
  `B` inside subspace `Z` (with `B` contained in `Z`), scan the RREF basis
  rows of `Z` in order and keep each row that increases the rank of `B`
  plus the rows kept so far. The kept rows are the complement basis. This
  rule is the only complement construction in the crate.
- `HomQuotient` stores the subspace and the complement rows; `reduce(v)`
  returns the pair (coordinates in the complement basis, member of the
  subspace) obtained by solving against the stacked complement-plus-RREF
  system. Representatives of quotient elements are complement-row
  combinations, so they are deterministic.
- Inclusion witnesses: `HomSubspace::witness_contains(f)` returns the
  solving coordinates, so a caller can recheck `coords * basis = f` by
  multiplication.

## 5. IndecomposableModule

```rust
pub struct IndecomposableModule { module: Module, endo: EndoAlgebra }

pub enum IndecError {
    Zero,
    Decomposable { summands: usize },
    Undetermined { attempts: u32 },
}
```

- `IndecomposableModule::new(m: &Module) -> Result<IndecomposableModule, IndecError>`
  builds `EndoAlgebra::new(m)` and requires `is_local()`. The zero module
  is `Zero`. A non-local endomorphism ring with a certified split is
  `Decomposable`; a Fitting bailout is `Undetermined`.
- Accessors: `module()`, `endo()`,
  `residue_degree() -> usize` defined as `endo.dim() - endo.radical_dim()`.
  For a local endomorphism algebra over F_p the quotient by the radical is
  a finite division ring, so a field F_{p^d} by Wedderburn; the accessor
  returns `d` times nothing else, and the name says degree, not field.
- `is_projective()` via `projective_dimension(m, 0) == Exact(0)`;
  `is_injective()` via `injective_dimension(m, 0)?` in the same way.

## 6. ExtSpace and ExtClass

`ExtSpace` retains what `ext_table` currently discards.

```rust
pub struct ExtSpace(Arc<ExtSpaceInner>);

struct ExtSpaceInner {
    source: Module,          // M
    target: Module,          // N
    degree: usize,           // n
    resolution: ProjectiveResolution,   // resolve(M, n + 1), minimal
    // cochain data at degree n, all in generator-block coordinates:
    cocycles: DenseMat,      // RREF basis of Z^n = ker delta^n
    coboundaries: DenseMat,  // RREF basis of B^n = im delta^{n-1}
    complement: DenseMat,    // deterministic complement of B^n in Z^n
    reps: Vec<Morphism>,     // one cocycle morphism P_n -> N per complement row
}
```

- Cochain coordinates are the existing generator-block Yoneda coordinates
  of `ext.rs` (`Layout`, `coordinates`), unchanged. The differential is
  `delta^k(f) = d_{k+1}.then(f)` with no signs, as established and
  justified in the v0.2 design.
- `ExtSpace::new(m, n, k) -> Result<ExtSpace, ExtError>` computes the
  resolution prefix, the two RREF bases, the complement by the fixed rule
  of section 4, and the representatives. `B^n` contained in `Z^n` is
  asserted; failure is a crate defect.
- `dim()` equals `complement.rows()` and must equal `ext_dim(m, n, k)`;
  the acceptance suite pins this equality on every fixture.
- Degree 0 is not special-cased away: `Z^0 = ker delta^0`, `B^0 = 0`,
  and `ExtSpace(M, N, 0)` is naturally isomorphic to `Hom(M, N)`. The
  identity class `ExtSpace(M, M, 0).identity_class()` is the Yoneda unit.
- Zero modules give zero spaces; no error.

```rust
pub struct ExtClass { space: ExtSpace, coords: Vec<Fp> }  // coords over the complement basis
```

- Arithmetic: `add`, `neg`, `scale`, `is_zero`, and equality, all
  requiring compatible spaces (source `ptr_eq`, target `ptr_eq`, equal
  degree). Incompatible operands are a typed error (`ExtClassError`), not
  `false`. (Deviation, recorded here: the spec first listed `PartialEq`.
  The implementation provides the fallible
  `equals() -> Result<bool, ExtClassError>` instead, because
  `PartialEq::eq` returns a bare `bool` and cannot carry
  `IncompatibleSpaces`, and a silent `false` on incompatible spaces is
  what this rule forbids. There is no `==` on classes; `equals` is the
  only equality.)
- `representative() -> Morphism` returns the complement-row combination,
  a genuine cocycle `P_k -> N`.
- `ExtSpace::class_from_cocycle(f: &Morphism) -> Result<ExtClass, ExtError>`
  checks that `f` is a cochain with the right endpoints, that
  `d_{k+1}.then(f) = 0`, then reduces modulo `B^n`. A non-cocycle is a
  typed error carrying the offending composite's coordinates.
- `ExtSpace::class_from_coordinates(coords)` validates length and entry
  canonicity.

## 7. Yoneda products (design bullet on product laws)

Endpoint order matches `Morphism::then`:

```text
ExtClass::then: Ext^m(M, N) x Ext^n(N, L) -> Ext^{m+n}(M, L)
```

Construction: let `f: P^M_m -> N` represent `alpha` and `g: P^N_n -> L`
represent `beta`. Compute chain lifts `phi_0, ..., phi_n` with
`phi_i: P^M_{m+i} -> P^N_i` such that

- `phi_0.then(augmentation_N) = f`, and
- `d^M_{m+i+1}.then(phi_i) = phi_{i+1}.then(d^N_{i+1})` for `0 <= i < n`.

Each lift solves a per-generator linear system with `DenseMat::solve`,
whose free variables are zeroed, so lifts are deterministic. The product
representative is `phi_n.then(g)`, reduced in `ExtSpace(M, L, m + n)`.

```rust
pub struct ProductWitness { lifts: Vec<Morphism> }
```

`ExtClass::then_with_witness` returns the class and the witness;
`ProductWitness::verify(alpha, beta, product)` rechecks the two lift
identity families, the reduction by multiplication and membership, and
that the product space's stored cocycle, coboundary, and complement bases
equal a fresh recomputation from the live endpoint modules. (Added during
the v0.4 review: membership alone cannot reject a tampered coboundary
basis when the raw product cocycle already lies in the complement span,
which holds on every cheap fixture, so the mutation bullet of section 15
needs the basis recomparison.) The plain `then` discards the witness.

Product laws are release gates, tested exhaustively on bounded fixture
degrees (every basis triple whose total degree stays in the tested range),
not spot-checked:

- Left and right Ext^0 units.
- Bilinearity over F_p.
- Changing a cocycle by a coboundary does not change the product class.
- Ext^1 Yoneda composition agrees with splicing constructed extensions.
- Associativity on all in-range basis triples.

## 8. ShortExactSequence

```rust
pub struct ShortExactSequence {
    sub: Module, middle: Module, quotient: Module,
    inclusion: Morphism,   // sub -> middle
    projection: Morphism,  // middle -> quotient
}
```

`ShortExactSequence::new(inclusion, projection) -> Result<_, SequenceError>`
checks, per vertex: the inclusion has full row rank (mono), the projection
has full column rank in the row-vector convention (epi), the composite is
zero, and `dim middle_v = dim sub_v + dim quotient_v`. Zero composite plus
the dimension equality plus mono plus epi force image equals kernel, so
exactness needs no further computation; the checks are stated in the error
type per vertex (`SequenceError::ExactnessFailed { vertex }` and friends).

Construction from a degree-1 class, `ShortExactSequence::from_ext1
(class: &ExtClass) -> Result<ShortExactSequence, SequenceError>` for
`class` in `Ext^1(M, N)`:

- `K = image(d_1)` with inclusion `kappa: K -> P_0`; the surjection
  `s: P_1 -> K` satisfies `s.then(kappa) = d_1`.
- The representative cocycle `c: P_1 -> N` kills `ker d_1 = im d_2`
  (minimal resolutions are exact by construction), so `c` factors as
  `s.then(c_bar)` with `c_bar: K -> N` computed by solving; uniqueness
  follows from `s` epi.
- `E = cokernel(mu)` for `mu = (c_bar, -kappa): K -> N (+) P_0`, built
  with `direct_sum` inclusions.
- `iota: N -> E` is the sum inclusion followed by the cokernel
  projection; `pi: E -> M` is induced by `(n, p) -> augmentation(p)`,
  which kills `im mu` because `im kappa = im d_1 = ker augmentation`.
- The result passes through `ShortExactSequence::new`. The zero class
  yields the split sequence.

Class recovery, `ShortExactSequence::ext1_class(&self, space: &ExtSpace)
-> Result<ExtClass, SequenceError>`: lift the augmentation `P_0 -> M`
through `pi` to `h: P_0 -> E`, observe `d_1.then(h)` lands in
`ker pi = im iota`, solve `c.then(iota) = d_1.then(h)` for
`c: P_1 -> N`, check the cocycle condition, reduce. The acceptance suite
pins the round trip `class -> from_ext1 -> ext1_class -> same class` on
every fixture and every basis class.

Split status:

```rust
pub enum SplitStatus { Split(SplitWitness), NonSplit(NonSplitWitness) }
pub struct SplitWitness { retraction: Morphism, section: Morphism }
pub struct NonSplitWitness { dual: Vec<Fp> }
```

The retraction system: unknowns are the entries of `r: E -> N` in the
fixed flat order (vertex-major, then row-major). Equations, in this fixed
order: the commuting squares in `(arrow, row, column)` lexicographic
order, then `iota.then(r) = id` constraints vertex-major and entry
row-major. This defines a matrix `A` and right side `b` deterministically.

- Split: `SplitWitness` carries `r` with `iota.then(r) = id` and `s` with
  `s.then(projection) = id`; `verify()` rechecks both identities and both
  morphism properties.
- Non-split: `NonSplitWitness.dual` is a vector `y` with `y A = 0` and
  `y b = 1`; the second identity pins its scale. (Deviation, recorded here:
  the spec first asked for a leading-1 normalization of `y` itself, but
  `y b = 1` already fixes the scale, and the implementation reads `y` off
  the pivot row of the reduced augmented system, whose pivot is the `b`
  column.) Existence of `y` proves the system inconsistent by
  multiplication alone; `verify()` rebuilds `A` and `b` by the fixed order
  and multiplies. The witness is found from the RREF of the augmented
  system.

`SplitStatus` is computed by attempting to solve the retraction system;
the two outcomes are exhaustive and each carries its proof.

## 9. Stable Hom and the AR socle construction (design bullets 1 and 2)

Fixed conventions, stated once and used everywhere:

- `D = Hom_{F_p}(-, F_p)` is the base-field dual.
- A map `f: M -> N` is projectively trivial when it factors through a
  projective module. Lemma (in the docs of `almost_split.rs`): `f` is
  projectively trivial exactly when it factors through the projective
  cover `pi_N: P(N) -> N`, because any projective factorization lifts
  through the cover. Therefore the projectively trivial subspace is the
  image of `Hom(M, P(N)) -> Hom(M, N)`, `h -> h.then(pi_N)`, computed as
  a `HomSubspace`.
- `stable_hom(M, N)` is the `HomQuotient` of `HomSpace(M, N)` by that
  subspace. `stable_end(M) = stable_hom(M, M)`.
- `End(M)` acts on `Ext^1(M, tau M)` on the right by precomposition
  pullback: for `phi` in `End(M)`, lift `phi` to a chain map
  `phi_i: P^M_i -> P^M_i` over the identity-lift recursion of section 7,
  and set `class . phi = class_of(phi_1.then(c))` for a representative
  cocycle `c: P^M_1 -> tau M`. Projectively trivial endomorphisms act as
  zero because `Ext^1(P, -) = 0`, so the action factors through stable
  End. The action is computed once as a matrix per radical basis element,
  in the fixed Ext basis.

The distinguished class (design bullet 1: deterministic, not canonical):

- Compute `S = { e in Ext^1(M, tau M) : e . r = 0 for every r in a basis
  of rad End(M) }` as the kernel of the stacked action matrices, stored
  RREF.
- Theorem (Auslander-Reiten-Smalo IV.2 with V.2; restated with proof
  sketch in the module docs): for `M` indecomposable non-projective over
  an Artin algebra, `Ext^1(M, tau M)` is dual to the stable endomorphism
  algebra of `M`, and the nonzero elements of its socle as a right
  `End(M)`-module are exactly the almost-split classes. The naturality of
  the duality is what turns socle membership into the right-almost-split
  property; the argument is cited, not re-proved in code.
- When the residue degree `d` of `M` exceeds 1, the socle has F_p
  dimension `d` and no basis-independent preferred element exists. The
  crate chooses the first RREF row of `S`. The API name is
  `chosen_ar_class`; documentation states that the class is deterministic,
  that any nonzero socle class gives an almost-split sequence isomorphic
  to the chosen one after suitable automorphisms of the end terms, and
  never claims a canonical class. (Corrected during the v0.4 review: this
  paragraph first said "unique up to equivalence of extensions", which is
  wrong. Distinct socle classes are inequivalent as extensions with fixed
  ends; only the sequences are isomorphic, through endpoint
  automorphisms.)

Duality consistency checks, both internal gates (never oracle fields):

- `dim_Fp Ext^1(M, tau M) = dim_Fp stable_end(M)`.
- `dim_Fp S = residue_degree(M)`.

A failure is `AlmostSplitError::Defect(DefectKind)` with

```rust
pub enum DefectKind {
    DualityDimensionMismatch { ext_dim: usize, stable_end_dim: usize },
    SocleDimensionMismatch { socle_dim: usize, residue_degree: usize },
}
```

which signals a crate bug, in the same spirit as `TauError::RoutesDisagree`.

## 10. AlmostSplitSequence

```rust
pub enum AlmostSplitOutcome { Projective, Sequence(AlmostSplitSequence) }

pub struct AlmostSplitSequence {
    sequence: ShortExactSequence,     // 0 -> tau M -> E -> M -> 0
    class: ExtClass,                  // the chosen AR class
    witness: AlmostSplitWitness,
}

pub enum AlmostSplitWitness {
    ArDuality(ArDualityWitness),
    ExhaustiveCatalog(CatalogWitness),
}

pub fn almost_split(m: &IndecomposableModule)
    -> Result<AlmostSplitOutcome, AlmostSplitError>;
```

- Input is `IndecomposableModule`, so decomposable input is unrepresentable
  rather than checked here. A projective `M` returns
  `AlmostSplitOutcome::Projective`: valid mathematics, not an error.
- The construction runs: `tau(m)` through the existing double-route
  cross-check; `IndecomposableModule::new(tau_m)` (the theorem makes
  failure a defect); the socle construction of section 9; the extension of
  section 8 for the chosen class; the non-split witness (the chosen class
  is nonzero because the socle RREF row is nonzero, and the witness proves
  it independently).
- `ArDualityWitness` stores: the radical basis coordinates of
  `End(M)`, the per-element action traces `e . r_j = 0` (coordinates whose
  recheck is one matrix multiplication each), the socle RREF, the chosen
  row index (always 0), the two dimension equalities of section 9, and the
  `NonSplitWitness`. `verify()` rechecks everything from the stored data
  plus the live modules.
- `CatalogWitness` (available on catalog domains, section 12) stores, for
  every catalog entry `X`, the factorization data for
  `im(Hom(X, E) -> Hom(X, M)) = rad(X, M)`: coordinates expressing each
  radical basis map as a composite through the right-hand map `g: E -> M`,
  and membership data placing each composite `Hom(X, E).then(g)` inside
  `rad(X, M)`. The dual left check against the catalog is also stored;
  the theorem makes it redundant, and the corpus keeps it because
  redundancy across independent routes is this crate's house style.
- `AlmostSplitError`:

```rust
pub enum AlmostSplitError {
    Tau(TauError),
    TauIndecomposability(IndecError),
    Hom(HomError),
    Defect(DefectKind),
}
```

## 11. Category radical (design bullet 6: rad and rad^2 exactly)

For certified indecomposables `X`, `Y` (as `IndecomposableModule`):

- If `X` and `Y` are not isomorphic (decided by `indecomposable_iso`),
  `rad(X, Y) = Hom(X, Y)` entirely.
- If they are isomorphic with a fixed deterministic isomorphism
  `u: Y -> X` (the first found by the deterministic scan of
  `indecomposable_iso`), then
  `rad(X, Y) = { f : f.then(u) in rad End(X) }`, a linear condition
  computed through `EndoAlgebra::coords` and the stored radical RREF. The
  subspace does not depend on the choice of `u`, because composing with an
  automorphism permutes the radical; the doc states this and the corpus
  checks it with a second isomorphism.

Both cases produce a `HomSubspace`, exact, with no catalog needed.

`rad^2` through a catalog `C`:

```text
rad2(X, Y) = sum over Z in C of span{ f.then(g) :
    f in basis rad(X, Z), g in basis rad(Z, Y) }
```

Composition order is `f.then(g)`, first `f` then `g`, matching the
crate-wide convention. The span is accumulated in flat coordinates and
stored RREF; the summation order over `Z` is catalog order, and the result
is order-independent because it is a span.

- With an exhaustive catalog, this equals the true `rad^2` (any
  factorization through an arbitrary module splits into catalog members;
  the radical is an ideal, so components stay radical maps). The lemma is
  stated in `arquiver.rs` docs.
- With anything less than an exhaustive catalog the same computation is
  only a lower bound. The API keeps the two apart by construction: exact
  `rad^2`, `Irr`, and AR quivers exist only behind `IndecomposableCatalog`
  values, which cannot be built from user-supplied module lists.

`Irr(X, Y) = rad(X, Y) / rad^2(X, Y)` as a `HomQuotient` with
deterministic representatives.

## 12. Catalogs and the valued AR quiver (design bullets 5 and the valuation correction)

```rust
pub enum CatalogProvenance { Nakayama, DynkinZeroIdeal }

pub struct IndecomposableCatalog {
    algebra: Arc<Algebra>,
    provenance: CatalogProvenance,
    entries: Vec<IndecomposableModule>,
}
```

- Constructors wrap the two existing complete enumerations:
  `IndecomposableCatalog::nakayama(algebra)` over
  `nakayama_indecomposables` and `IndecomposableCatalog::dynkin(algebra)`
  over `dynkin_indecomposables`. Entry order is enumerator order; the
  stable catalog identifier of an entry is its index. Completeness
  provenance is the wrapped theorem (Nakayama classification, Gabriel);
  a plain module list can never become a catalog.
- `ar_quiver(algebra: &Arc<Algebra>) -> Result<ArQuiver, ArQuiverError>`
  dispatches deterministically: zero ideal and Dynkin shape first, then
  Nakayama shape, else
  `ArQuiverError::UnsupportedDomain { dynkin, nakayama }` carrying both
  rejections.

```rust
pub struct ArVertex {
    id: usize,
    module: IndecomposableModule,
    residue_degree: usize,
    projective: bool,
    injective: bool,
}

pub struct ArArrow {
    source: usize,
    target: usize,
    base_dim: usize,               // dim_Fp Irr(X, Y)
    over_source_residue: usize,    // dim over the source residue field
    over_target_residue: usize,    // dim over the target residue field
    representatives: Vec<Morphism>,
}

pub enum ArrowValuation {
    Plain(usize),
    Valued { base_dim: usize, over_source: usize, over_target: usize },
}
```

- An arrow exists exactly when `base_dim > 0`. Arrows are ordered by
  `(source, target)`.
- `over_source_residue = base_dim / d_X` and
  `over_target_residue = base_dim / d_Y`; both divisions must be exact,
  and a remainder is a crate defect error, because `Irr(X, Y)` is a
  vector space over each residue field.
- `ArArrow::valuation()` returns `Plain(base_dim)` only when both residue
  degrees are 1; otherwise `Valued { .. }`. There is no bare integer
  `multiplicity` accessor and no `None` whose reason the caller must
  remember.
- On the two v0.4 catalog domains every indecomposable is a brick or
  uniserial with residue degree 1, and the acceptance suite asserts this.
  (Deviation, recorded here: this bullet first promised valuation
  arithmetic exercised at the `rad`/`Irr` level by the F_8-endomorphism
  fixture of `decompose_iso.rs`. No cheap fixture yields a nonzero valued
  `Irr`, and the catalog domains provably cannot, because every entry has
  residue degree 1, so no fixture ever constructs
  `ArrowValuation::Valued`. What is exercised instead: the
  residue-degree division bookkeeping runs on the F_8 module at the `rad`
  level in the `arquiver.rs` unit tests, and the `Valued` arithmetic with
  its exact-division defect path is pinned by the in-module test
  `valued_arrow_arithmetic_and_the_division_gate_are_pinned`, which builds
  `ArArrow` values directly through the same division routine
  `ar_quiver` calls.)
- Cross-check (release gate): for every non-projective catalog vertex
  `M`, the middle term of its almost-split sequence decomposes by
  `krull_schmidt` into catalog members whose multiplicities equal
  `over_source_residue` of the corresponding arrows into `M`, and the
  `ArDuality` witness route and the `ExhaustiveCatalog` witness route
  must both validate the same sequence.

No work budget is introduced for AR-quiver construction in v0.4: both
catalog domains are bounded (at most `dim A` respectively 120 entries), so
the pair loop is small and exact. Consequence of the consensus rule "no
truncation state unless a budget is actually enforced": there is no
AR truncation error, and a constructed `ArQuiver` is always complete for
its domain. If a later release adds larger domains, it adds the budget and
the typed partial result then.

## 13. Edge cases (design bullet 4)

The suite pins each of these:

- Degree 0: `ExtSpace(M, N, 0)` dimension equals `hom_dim`, unit classes
  compose as identities.
- Zero modules: `ExtSpace` with a zero endpoint has dimension 0;
  `ShortExactSequence` with zero sub or zero quotient reduces to an
  isomorphism witness; `IndecomposableModule::new(zero)` is
  `IndecError::Zero`.
- Projective `M`: `almost_split` returns `Projective`; `tau` returns
  `Tau::Zero`.
- Decomposable input: unrepresentable for `almost_split`
  (`IndecomposableModule` gate); `IndecError::Decomposable` from the
  wrapper.
- The zero Ext^1 class: `from_ext1` yields the split sequence with a
  `SplitWitness`.
- Empty catalog: impossible (a positive-dimensional algebra has at least
  one simple per vertex; both enumerators return at least `num_vertices`
  entries); asserted, not handled.
- Isolated AR vertices (no incoming or outgoing arrows): legal output.
- Characteristic 2: every acceptance family runs over F_2 and F_5 at
  minimum, matching the v0.3 matrix.

## 14. Determinism (design bullet 7)

Everything public is deterministic across processes and platforms: Hom
bases (kernel RREF), Ext bases (RREF plus the fixed complement rule),
chain lifts (`solve` with zeroed free variables), chosen AR classes (first
socle RREF row), catalog identifiers (enumerator order), arrow order
(source-major). Gates:

- A fresh-process fingerprint test in the style of `determinism_cert.rs`
  hashes: the flat Ext basis matrices for fixed fixture triples, the
  chosen AR class coordinates, and a normalized AR-quiver rendering
  (vertex dim vectors plus valued arrows) for one Nakayama and one Dynkin
  fixture.
- The normalized AR-quiver renderings are committed as golden snapshot
  files beside the golden certificates, compared byte for byte, with the
  same `GOLDEN_CERT_WRITE=1`-style regeneration escape hatch and the same
  `.gitattributes` protection.

## 15. Mutation corpus (design bullet 8)

Every checking constructor and every `verify()` must reject a targeted
mutation. The corpus covers at least: a non-exact sequence at one vertex;
a tampered inclusion that is not a morphism; a cocycle failing
`d.then(f) = 0`; coordinates of the wrong length; a complement row
replaced by a coboundary; a lift family violating one lift identity; a
product reduced against a tampered coboundary basis; a split witness whose
retraction fails the identity by one entry; a dual vector with
`y A != 0`; a dual vector with `y b = 0`; an action trace claiming
`e . r = 0` falsely; a socle RREF containing a non-socle row; dimension
equalities off by one in each `DefectKind` direction; a catalog witness
missing one factorization; a valued arrow with a non-dividing residue
degree; and a forged catalog provenance (constructed only through the
public API, so the test asserts unconstructibility by API absence, not by
runtime check).

## 16. QPA oracle schema v6

Frozen only after the capability spike reports what GAP plus QPA can
independently produce. Binding constraints, spike-independent:

- Oracle fields are basis-independent invariants only: dimensions, ranks
  of named maps between named spaces, multiplicities, lexicographically
  sorted dimension-vector multisets. Never coordinates, bases, or raw
  matrices.
- The Yoneda field name is `yoneda_map_rank`, the rank of the bilinear
  multiplication map on specified `(M, N, L, m, n)`, and it enters the
  schema only if the spike shows QPA computes it independently.
- Almost-split fixtures carry start, end, and middle-term Krull-Schmidt
  identifiers (sorted dimension vectors with multiplicities), per fixture
  prime field.
- Irreducible-morphism fixtures carry `Irr` base dimensions and
  valuations on catalog domains.
- The internal duality consistency checks of section 9 stay out of the
  schema.
- `qpa_expected.json` is regenerated only by a real GAP run per the
  existing oracle policy, never from library output, and the v5 fixture
  content is preserved under the v6 envelope.

## 17. Python surface

New classes: `HomBasis` is not exposed; the Python surface follows the
consensus decision surface exactly.

- `Module.ext_space(other, degree) -> ExtSpace` with `dim`, `basis()`
  returning `list[ExtClass]`, `class_from_coordinates(coords)`.
- `ExtClass`: `source`, `target`, `degree`, `coordinates`,
  `representative()` (as a `Morphism`), `__add__`, `__neg__`, scalar
  `__mul__`, `__eq__` (typed error on incompatible spaces), `is_zero`,
  `then(other)`, `extension()` for degree 1.
- `ShortExactSequence`: `sub`, `middle`, `quotient`, `inclusion`,
  `projection`, `ext1_class()`, `split_status` exposing either
  (`retraction`, `section`) or the normalized inconsistency vector,
  `verify()`.
- `Module.almost_split()` returns either an `AlmostSplitSequence` or the
  enum member `AlmostSplitOutcome.PROJECTIVE`; never `None`. Decomposable
  or undetermined input raises the `ValueError` subclass
  `NotIndecomposableError`.
- `AlmostSplitSequence`: `start`, `middle`, `end`, `inclusion`,
  `projection`, `ext1_class()`, `witness_route` (string enum
  `"ar_duality"` or `"exhaustive_catalog"`), `verify()`, and a compact
  `verification_summary()` mapping check names to booleans.
- `Module.category_radical(other)`: `dim` and `basis()` of morphism
  representatives; requires both endpoints certified indecomposable and
  raises `NotIndecomposableError` otherwise.
- `Algebra.ar_quiver()`: vertices with `id`, `module`, `residue_degree`,
  `projective`, `injective`; arrows with `source`, `target`,
  `base_field_dim`, `dim_over_source_residue`, `dim_over_target_residue`,
  `representatives()`; a `plain_multiplicity` accessor that raises a
  typed error when a residue degree exceeds 1 instead of guessing.
  Unsupported domain raises `UnsupportedDomainError(ValueError)` naming
  both failed dispatch routes.
- Error taxonomy (design bullet 10): invalid endpoints, incompatible
  spaces, decomposable input, and unsupported catalog domains are
  `ValueError` subclasses; internal defect cross-check failures are
  `RuntimeError` subclasses (`DefectError`); budget exhaustion keeps the
  existing `TruncationError`, re-parented under a new
  `BudgetExhaustedError(RuntimeError)` base so future operation-specific
  budget errors share it. Re-parenting preserves every existing catch
  site because `TruncationError` remains a `RuntimeError`.
- Projective almost-split outcomes are outcomes; they never raise.

## 18. Acceptance matrix

Two honestly separated tiers:

- Ext objects, Yoneda products, extensions, and AR-duality almost-split
  sequences run on the full v0.3 non-monomial matrix: the commutative
  square over F_5, preprojective A3 over F_2, the inhomogeneous family
  over F_5, plus monomial fixtures over F_2 and F_5.
- Full AR quivers, catalog-exact rad^2, `Irr`, and `ExhaustiveCatalog`
  witnesses run where an exhaustive catalog exists: Nakayama fixtures
  (including `truncated_poly` and cyclic Nakayama) and zero-ideal Dynkin
  fixtures (A_n, D_4, orientation variants). Preprojective A3 is
  representation-finite but has no certified catalog in this release; it
  runs tier 1 only. The docs say exactly this.

Hand-derived expected values pin at minimum: the AR sequences of
`k[x]/(x^n)` (uniserial middle terms), linear A_3 (all six vertices of
the AR quiver with its arrows), D_4 subspace orientation (the
3-arrow star), and one cyclic Nakayama algebra; Ext^1 dims and one
nonzero Yoneda square on `k[x]/(x^3)`.
