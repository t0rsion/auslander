# Public v0.9 validation

This record describes local v0.9.0 checks against the v0.8.0 baseline.
It does not record publication or cross-platform CI results.

## Functional scope

Catalog queries cover Nakayama, zero-ideal Dynkin, and checked gentle-tree
algebras over prime fields. Atlas artifacts retain the selected catalog,
field, certificate, target dimensions, degree bound, limits, status, and rows.
Replay rebuilds that scope and compares the full enumeration or exact cut
prefix. Generic Ext checks run separately from cached score calculations.

The Python workflow includes field binding, mixed-field saved sessions,
status explanations, higher orthogonality, catalog coordinates, and portable
atlas reports. The script and notebook run from an installed package. Their
Ext tables label both source and target catalog entries.

## Independent mathematical evidence

The gentle-tree oracle invokes GAP/QPA to enumerate strings and compare
indecomposables, Hom, Ext, AR sequences, and irreducible maps. The committed
fixture records its GAP/QPA provenance. It is generated by GAP/QPA, never
from this library. See the [oracle instructions](../crates/auslander/tests/qpa-oracle/README.md).

The complete live oracle run passes. Artifact tamper tests recompute the
checksum before replay, so rejection checks the mathematical rows and
coverage rather than only the checksum. They cover omitted, duplicated,
reordered, and changed rows, including a false complete status on a cut.

## Source review

The production-line scanner measures 38372 code lines across
232 baseline files and 42336 code lines across 250 release files.
The increase is 3964 code lines. The release ceiling equals the measured
release count.

The source review keeps typed error boundaries, proof checks, and test
coverage. It removes duplicate dispatch and separates materialization,
score arithmetic, and artifact replay into named checks. It does not
compress code to meet a line limit.

Core atlas preflight and artifact work planning retain separate checked
arithmetic. Core failures carry atlas error variants; artifact failures name
untrusted fields. Their check order differs. Sharing a helper would require
an error adapter and would not remove either validation boundary.

The complexity audit records
537 maintained source files and 131006 physical lines, compared with
489 files and 117301 physical lines at the baseline. These counts include
bindings, tests, examples, Python stubs, and GAP sources.

The audit measures 9882 callable scopes: 9214 in band 1-5 and
668 in band 6-10. Maximum callable complexity is 10;
18 macro templates have maximum complexity 4. No scope exceeds the
policy ceiling. Macro expansion complexity is not measured.

The source review covers touched or new scopes in band 6-10.
The quality workflow retains the full audit as a CI artifact.

## Public source and package review

The public source review removes private development records, session
identifiers, and local-only commit references. Package inspection checks
private build paths, archive member paths, licenses, and versions. The
[release checklist](releasing.md) requires these checks on CI distributions
before publication.

## Verification scope

A replayed cut remains a cut. A finite Ext table makes no claim about degrees
above its bound, Yoneda products, or general string-algebra classification.
Named work limits do not bound all intermediate matrix storage or elapsed
time. Atlas operations do not provide cooperative cancellation.

The [benchmark record](catalog-benchmarks.md) reports setup, query,
materialization, artifact construction, and replay separately. Its timing
sample is machine-specific and supplies no general speed guarantee.
